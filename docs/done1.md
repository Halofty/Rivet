# Milestone 1 — 정적 애플리케이션 셸

작성일: 2026-09-17

## 구현 내용

프로젝트 목록, 프로젝트별 보드, 이슈 상세를 이동할 수 있는 공통 Web/Desktop 화면을 구현했다. 이 단계의 데이터는 고정된 예시이며 데이터베이스나 실제 생성·저장 기능은 포함하지 않는다. 모든 화면에 미리보기 안내를 표시하고, 폼 제출 결과도 저장 성공으로 표현하지 않는다.

| 경로 | 화면 |
| --- | --- |
| `/` | 개요와 프로젝트 카드 |
| `/projects` | 프로젝트 목록과 생성 폼 미리보기 |
| `/projects/:project_id` | 프로젝트 정보, 상태별 이슈 보드, 생성 폼 미리보기 |
| `/issues/:issue_id` | 이슈 상세와 로컬 편집 미리보기 |
| `/dev/connection` | Milestone 0의 서버 연결·메시지 점검 |
| 기타 경로 / 없는 ID | 찾을 수 없음 안내와 프로젝트 목록 복귀 링크 |

`Route` 열거형과 `Link`, 공통 `AppShell`/`Outlet`으로 탐색을 구성했다. ID는 `i64`로 파싱하며 잘못된 ID 형식도 fallback에서 처리한다. 프로젝트·이슈가 바뀔 때 ID 기반 key로 페이지 상태를 새로 만들므로 이전 항목의 편집 초안이 다음 항목에 섞이지 않는다.

`ProjectList`, `IssueBoard`, `StatusBadge`, `ProjectForm`, `IssueForm`, `EmptyState`, `MissingRecord`를 분리했다. 폼은 props와 이벤트로 부모 화면과 통신하고, 입력·오류·미리보기 상태는 필요한 컴포넌트에만 둔다. 컴포넌트에는 데이터베이스 의존성이 없다.

`src/demo.rs`에는 프로젝트 3개와 이슈 6개를 두었다. 보드는 프로젝트 ID로 이슈를 제한하고 Todo → In Progress → Done 순서로 묶는다. 빈 프로젝트와 비어 있는 상태 열도 표시한다. 이 자료형은 화면 예시용이며 Milestone 2의 영속 도메인 모델이 아니다.

공통 CSS에 사이드바, 카드, 보드, 폼, 오류·안내 메시지, 좁은 창에서의 단일 열 배치를 추가했다. label과 입력을 연결하고 키보드 포커스 표시, 본문 바로가기, 오류 알림과 상태 메시지를 제공한다.

## 코드 리뷰 및 수정

- **편집 상태 선택 오류 수정:** 실제 Web 검증에서 In Progress 이슈를 편집하면 선택 상자가 Todo로 표시되는 문제를 발견했다. 각 option의 `selected`를 현재 상태와 연결해 최초 표시가 초안 상태와 일치하도록 수정했다.
- **재시도 시 입력 유지:** 연결 점검의 입력 signal과 action을 재생성되는 로더 ErrorBoundary 밖으로 옮겼다. 연결 재시도가 폼 초안까지 초기화하던 Milestone 0의 구조적 문제를 수정했다.
- **미리보기 범위 명시:** 이슈 상세 편집은 해당 페이지에서만 반영된다. 목록·보드는 고정 예시를 유지하고 페이지를 떠나면 편집 미리보기를 초기화한다. 실제 저장·로더 갱신은 Milestone 3–4에서 구현한다.
- **검증 경계:** UI 검증은 프로젝트 이름 1–100자, 이슈 제목 1–200자, 설명 최대 10,000자를 검사한다. 서버 저장 기능이 추가될 때 공통 도메인 검증과 서버 검증으로 통합해야 한다.
- **확인 범위:** 찾을 수 없음은 화면과 라우팅 처리이며 HTTP 404 상태 코드까지 구현한 것은 아니다. 외부 배포 및 영속 데이터 접근 오류 처리는 이번 단계의 검증에 포함하지 않는다.

## 검증 결과

`scripts/check.ps1`을 수정본 기준으로 실행해 모두 통과했다. Web은 `wasm32-unknown-unknown`으로, Desktop·Server는 각각의 feature로 검사했다.

| 검사 | 결과 |
| --- | --- |
| rustfmt | 통과 |
| Web / Desktop / Server `cargo check` | 모두 통과 |
| Web / Desktop / Server Clippy | 모두 통과 |
| typed route 테스트 | 2개 통과: URL 왕복, 잘못된 경로·ID fallback |
| 서버 transport 테스트 | 3개 통과: 요청 context, Unicode 왕복, 구조화된 HTTP 400 |
| DX Web 빌드 | 성공 |
| DX Desktop 빌드 | 성공 |
| `git diff --check` | 통과 |

Web의 실제 브라우저에서 프로젝트·이슈 링크 이동, 상세 직접 URL, 뒤로/앞으로 이동, 편집 미리보기 초기화를 확인했다. In Progress 초기 선택, 한국어 제목과 Done 변경, 빈 제목 오류, 프로젝트 이름 오류와 Enter 제출도 확인했다. `/projects/3`의 빈 보드, 없는 프로젝트·이슈 ID, 알 수 없는 경로와 숫자가 아닌 ID는 각각 안내 화면을 표시했다.

연결 점검에서는 빈 메시지의 서버 검증 오류 이후 한국어 메시지를 다시 보내 `Rivet received: 안녕하세요 Rivet` 응답을 확인했다. Tab → 본문 바로가기 → Enter → Tab 순서로 본문 첫 링크에 도달했다. 1280px 화면과 390px 화면을 살펴보았고, 좁은 화면은 단일 열로 배치되며 문서 폭을 넘는 가로 스크롤이 없었다.

첫 Desktop 빌드는 약 411초가 걸렸으며 실제 Windows 창에서 공통 개요 화면을 확인했다. 크레딧 중단 후 오래 유지된 개발 연결이 응답하지 않아 직접 실행한 개발 프로세스를 종료하고 새로 실행했다. 재실행 후 개요, 세 상태 열의 보드, 이슈 상세, In Progress 편집 초기 선택, 미리보기 제출 결과와 보드 복귀를 확인했다. 연결 화면의 `Rivet is connected` 및 `Desktop 확인` 한국어 입력도 확인했다. 마지막 Desktop 메시지 제출 전에 사용자가 Escape로 Computer Use를 중단하여 추가 UI 검증을 종료했다. Desktop echo 응답·연결 복구와 전체 키보드/fallback 동작은 미확인 항목으로 남긴다. 따라서 구현은 마쳤지만 계획의 모든 플랫폼 완료 조건을 검증했다고 표시하지 않는다.
